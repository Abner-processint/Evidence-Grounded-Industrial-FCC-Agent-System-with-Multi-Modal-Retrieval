# 讨论：阈值多来源冲突（发给 GPT 6.2 Astra 的材料与回复，2026-11-18）

> 本机 Codex CLI（gpt-6.2-astra，只读、空目录），材料经标准输入发送；含 TIA3216 / TR3217 / LRC3201 等位号的报警定值与文档名。

## 发出的材料


背景：催化裂化（FCC）装置问答智能体（n8n 工作流，DeepSeek 作写回答模型）。用户问「2025 年 1–3 月分馏塔底温度是否超过报警值」这类题时，代码先从检索到的证据表格里取该位号的报警四档（HH/H/L/LL），再与历史库实测极值做确定性比对，比对结果作为结构化条目（established_thresholds，turn_ref=computed）交给写回答的模型，提示词要求「越限题必须直接采用这些条目」。

### 用户定下的规则（不可改）
1. 同一个量有多个取值（多份文档冲突）时，全部并列列出、各给判断，系统不替用户择一。
2. 回答之间不能矛盾；宁可不说，不说错。
3. 防错靠流程位置、结构化数据、代码计算，不写正则词表去匹配回答文字。

### 这次发现的问题（新会话，R10 题）
- 证据里 TIA3216（分馏塔底油浆温度）有三套报警定值：
  - 报警位号表（DCS 导出，列名 PVHHALM.TP/PVHIALM.TP/PVLOALM.TP/PVLLALM.TP）：HH 空、H 355、L 310、LL 305；
  - 《DCS 控制点统计表》控制回路统计页：HH 348、H 345、L 310、LL 305；
  - 同表 Sheet2：HH 350、H 345、L 280、LL 0。
- 原代码按「行数唯一最多的一套」取表格定值；三套各 1 行打平 → 直接放弃，也不记冲突 → TIA3216 无比对。
- 只有邻近位号 TR3217（油浆抽出温度，4 行一致 H 340/HH 345）有比对；提示词强制「越限题必须用 computed 条目」，模型就把 TR3217 的结论（34 天高于 HH 345）当成塔底温度的答案。
- 另外提示词那节标题叫「本次对话中已确认的阈值」，模型在新会话里写出「按本次对话已确认的阈值」——假出处。约 5% 的回答有此类说法。

### 已在测试副本上做的修正（r1119t）
1. 表格打平时：逐档汇总各套取值；只有一个取值的档位照常登记，取值不同的档位记为冲突（带每个取值的出处表名），比对句对每个取值各给一次判断；出处写「几套定值行数相同，未择一」。但要求各套都点名同一位号；几套分属同回路不同位号（LRC3201A / LRC3201B）时不算冲突、仍不登记。
2. 比对行最多保留 2 行；排序改为：前面轮次给过阈值的 → 本轮主分析读到的位号 → 因子解析附带读到的位号（原先所问位号可能被挤掉）。
3. 提示词标题改为「阈值与确定性比对」，并写明：computed 条目按条目写明的出处写（表名），不得写成「本次对话已确认」；每条只适用于它写明的位号，所问位号没有条目时不得拿其他位号的结论代替。守卫节点置顶段的固定前缀也去掉「本次对话已给出」。

离线回放（68 次执行、101 次节点运行，旧代码离线结果与线上记录 101/101 一致）：95 次不变，6 次变化，全是打平的位号由「无比对」变为「列出各套取值并分别判断」；R10 改后得出：实测最大 350.45 高于 H 345；HH 348（控制回路统计页）/ 350（Sheet2）均被越过；（报警位号表的 H 355 这次因为该表那一行没进本轮证据包而没出现）。

### 想和你讨论的问题
1. **没打平时仍按多数行取一套**（比如 3 行 vs 2 行），另一套只在比对句末尾提一句「属另一套定值，比对以本句为准」。这和规则 1「不替用户择一」是否冲突？是否应该一律并列？代价是什么（PDRA3125 那类 12 行里 8 行一致的场景）？
2. **来源性质能否进结构而不择一**：报警位号表是 DCS 组态导出（PV*ALM.TP 列），控制点统计表是人工整理表。能否在比对句里标注来源性质（"DCS 组态导出" vs "人工统计表"）帮用户判断，而不违反「不择一」？这算不算变相择一？
3. **未组态填 0**：Sheet2 的 LL 0 明显是未组态，被当作候选值（「未低于 0」）。有什么不写死规则的处理办法？（例如以量程下限比较？只在等于量程下限或 0 且其他来源非 0 时标为「疑似未组态」？）
4. **回路键粒度**：代码用「首字母+数字」作回路键（LT3201B、LRC3201A、LRC3201B 都归 L3201），表格定值按回路汇总。这次我用「各套都点名同一位号才算冲突」兜住打平分支，但多数行分支仍按回路取值、可能把 A 表的定值用到 B 表的比对上。值得改成按位号吗？风险？
5. **提示词里「所问位号没有条目时不得拿其他位号结论」**这种约束是靠模型自觉；有没有更结构化的做法（比如代码标出「所问量对应的位号」，没有比对时由代码给出「本轮未能对所问位号做比对」的条目）？注意规则 2：要说「没有」就不说，否则可能与资料矛盾。
6. 还有什么我们没想到的风险（多轮对话时冲突登记的保存与沿用、比对句变长导致模型抄错、等）？

## GPT 6.2 Astra 回复（原文）

**1. 多数行取一套，和规则 1 冲突。** 3 行对 2 行时，只要两套都指向所问位号、同一档位和相同适用条件，就应并列给出判断。「属另一套定值，比对以本句为准」已经替用户选了。R10 正好说明少数值为什么重要：如果三份证据都取到了，同一个最大值 350.45 **高于 H 345，却低于 H 355**。省掉一个值就会改变答案。

建议取消多数与打平两个业务分支，统一按「位号、档位、不同取值」计算，保留每个取值对应的来源和原始行。PDRA3125 的 12 行若有 8 行相同，这 8 行只需展示一次，其余按实际不同值展开。代价主要是不同值多时答案会变长；可以用表格压缩重复文字。四档还要保留原始套组关系，避免把一张表的 H 355 和另一张表的 HH 348 拼成同一套组态。某表 HH 留空，也只表示该行未提供 HH 数值。

**2. 可以标来源性质，不算择一。** 用户可以据此自行判断。建议为每个值保留来源类型、文件、工作表、行位置，以及能查到的版本或导出日期。R10 的两个不同 HH 来自同一文件的不同工作表，只写文件名还不足以复核。

「DCS 组态导出」和「人工统计表」可以并列展示。来源性质应来自已核实的文件登记或导出说明，仅凭 `PV*ALM.TP` 列名不足以认定文件的生成过程。只要来源类型不决定哪个值有资格展示、哪个值用于总判断，就符合规则 1。导出日期和组态生效日期也应分开记录，尤其是回答 2025 年一季度的问题时。

**3. 仅凭现有信息，我不能确定 Sheet2 的 LL 0 表示未组态。** 建议分别保存「单元格原值」「该档配置状态」「状态依据」。有适用于这张表的填表说明、字段字典或同档配置标志，才按其语义处理。例如，说明明确规定 0 是占位值，就保留原值供追溯，跳过该档数值比对；若标志只说明该档已停用，就记录“已停用”，不要进一步推成“未组态”。

`0`、等于量程下限、与其他来源不同，都可以作为复核线索，不能单独决定跳过。证据不足时可写 **「Sheet2 的 LL 栏填 0，含义待核实」**。若有合格的实测最小值，再给条件判断「若按该栏数值比较，实测最小值……」。这样既保留了这个候选，也不会把「未低于 0」写成已经核实的低低报警结论。

**4. 值得改。回路键用于找候选，阈值比对绑定到具体位号。** 应在统计行数、合并定值之前校验对象，让多数、打平、单一来源都经过同一处检查。`L3201` 可以召回 `LT3201B`、`LRC3201A`、`LRC3201B`，其中任何一个点的阈值要用于另一个点，都需要能核实的报警配置映射。同回路、共用测量信号，都不足以证明共用报警定值。

改细的代价是旧表里的简称、历史库别名、合并单元格承接的位号可能漏配。先恢复表格上下文，再使用有出处的别名映射；对象键至少包含装置和完整位号，保留 A/B 后缀。上线前可单独回放“原来靠回路键才有比对”的记录，区分可补映射的漏配与应当撤掉的串点结论。

**5. 把「所问位号」做成检索和计算的输入，并让代码直接渲染越限答案。** 我会按以下顺序改 n8n 流程：

1. 从本轮问题解析目标。用户给了位号就精确绑定；只给“分馏塔底温度”时，用已核实的测点映射解析。若仍有两个合理候选，就请用户区分测点。不能用“哪个位号恰好有 computed 条目”反推用户问的是谁。
2. 按目标位号对已索引的定值表做一次精确补查，取齐匹配行，再和该位号、该时段的实测数据比对。**这是 R10 仍缺的一步**：报警位号表那行没进证据包，后面的并列逻辑再正确，也写不出 H 355。
3. 每个所问位号生成一条结果记录，里面容纳所有候选值及判断。所问对象不受“两行”上限裁剪，历史轮次和因子分析带出的位号不能占用它的名额。纯越限题直接由代码渲染最终答复；混合题也由代码插入比对表，模型只写其他部分。
4. 若目标已确定但计算没完成，内部记录具体原因。需要回应时可以只说 **「本轮未完成 TIA3216 在该时段的比对」**；若产品约定此时静默，就省略判断。这句话描述的是本次执行，不能扩写成“资料没有报警值”。`turn_ref=computed` 同样只描述结论的生成方式，阈值出处直接取证据字段。

**6. 还要优先防三类错误。**

- **跨轮把条件判断变成既定事实。** 保存带出处的候选集合、适用时段和版本。用户说“这次按 345 算”，应另存为本轮假设。后续新取到 H 355，就合并证据并重算；上一轮的单值或自然语言结论不能覆盖新来源。若无法确认哪版在一季度生效，就逐来源写“按该表数值比较”；若能确认中途改值，就分时段计算。
- **把极值比较升级成报警事件或天数。** 一个合格样本足以证明曾高于某值；覆盖不全时，反方向最多能说“已取得的有效样本均低于该值”。季度最大值本身也推不出“34 天”，天数须按约定时区逐日计算。比较时用原始精度，并区分“超过”和“等于”；是否实际触发报警还取决于组态或事件记录。[OPC UA 限值报警定义](https://reference.opcfoundation.org/specs/OPC-10000-9/5.8.18)也明确指出，值正好等于限值时的报警行为取决于具体实现。
- **回放只验证哪些输出变了。** 101/101 说明旧逻辑能在离线环境复现，不能证明其余 95 次都答对。建议补几个有明确预期的回归断言：复制或打乱同一来源的行，候选值和判断不变；加入同回路 B 位号，A 的结果不变；R10 补回报警位号表后，H 345 与 H 355 各有判断、各带出处；删去 TIA3216 的可比证据后，最终答案中不会出现 TR3217 的“34 天”。这些都可以检查结构化结果和固定模板，无需匹配模型措辞。
