## 一、问题性质

| 成因 | 具体表现 |
|---|---|
| 按字数截短 | 长记录的尾部字段（上界标高、取压点）随截断点随机丢失；结构化字段一直完整，但原来不送给模型 |
| 席位上限 | 证据包席位固定，切题的证据排在后面就进不去，回答便说「未检索到」 |
| 证据只写了「有」，没写值 | 读数结果只写行数，自查据此判为已有，计算那一步就拿不到统计量 |
| 结构化信息没进证据 | 知识库的别名、备注只在知识库节点里，证据只写名称和口径 |
| 代码静默丢弃 | 计算量定义的编号对不上清单就跳过，不留原因 |
| 错误量级看起来合理 | 分母、表选错时结果仍在常见范围内，原有核对只看数据有没有、单位对不对 |
| 同一路两块表 | 单看位号描述，分不出是同一路的两个测点还是两路物料（回炼油浆 FI3251 / FRC3250） |
| 模型抄错编号 | 检索库编号是 32 位长串，模型偶尔抄错一位 |
| 同一块表配给两个量 | 模型给「回炼油」配表时只找到回炼油浆表，于是两个量都用了 FRC3250 |
| 改动不完整 | 删节点时改了出口数，没改决定走哪个出口的表达式 |
| 「没有」没有核对过 | 回答说「未检索到」之前，没有一步去本轮全部资料里核对，也不会按位号专门去查 |
| 模型配置拖慢 | 规划两步的模型大部分时间在内部推理；写首稿时按旧规则把证据原样抄回，撑满输出上限 |

### 三）常识检查

**8. 计算结果的常识检查**（`COMMON_SENSE_CHECK_V1`，11-01 23:31Z，c30cd82f，新增 5 个节点）

- **来由**：用户 11-01 提议，把「自我发挥」用作直觉检查和通用知识检查。
- **做法**：计算那一步之后，模型只看问题、装置知识库和每个计算量的名称、算式、输入名称 / 单位 / 位号，不看数值。它先写出该量的标准定义再对照算式，并给出结果和输入「出了会吃惊」的范围。代码比较数值，范围外 3 倍以上、或定义问题标为确定的，才记为疑点。
- **疑点怎么用**：写进该计算量的证据行，标「待核实；使用该值时须同时说明并以证据核实」。不改数值、不改状态；没有算出的量时不调用。
- **离线试验台**：21 条真实计算结果，按厂里口径人工标 13 错 8 对，每条跑 2 次。第三版抓到真实错例 21/26，对的结果误报 2/16；人为造的单位错，结果抓到 12/16，输入抓到 10/16。
- **漏报**：比值类结果错 60–100 倍后仍落在合理范围内的，抓不到。这是用 3 倍余量换少误报的代价。
- **实测**：副本 6 题中有算出结果的 3 题（柴油收率 21.45%、加速蒸汽 0.9193%、回炼比 0.01604）都没被标，无误报；每次检查 1–2 秒。

**9. 公式里同一路两块表相加**（`FORMULA_SUM_CHECK_V1`，11-03 20:50Z，f29d5bcb，在第 8 项上原地扩充，不加模型调用）

- **来由**：11-03 主线回归 T6，回炼比结论为 0.03016 = (FI3251 3.70 + FRC3250 4.20) / 262.13。调研资料写明 FI3251 是油浆脱固回炼浓缩油浆量，FRC3250 是油浆泵出口回炼油浆量，很可能是同一路的两处计量。
- **改后**：检查时给每个输入附上 DCS 画面描述，并判断公式里相加的几项是否同一路（同一路 / 不同路 / 判不清）。同一路和判不清的记为疑点，由代码把每项轮流置零重算出「只取其一」的备选值；结论处备选值与原值并列，系统不替用户择一。
- **过程中的更正**：第一版有误报（说 FIC3260 不是新鲜进料等）。补上「知识库列出的表就是对的」「变量名宽松不算问题」后，误报消失；但只看描述判同一路不稳，所以把「判不清」也纳入提示。
- **结论**：机制可用，根本解法是请厂里确认回炼油浆以哪块表为准（见四）。
