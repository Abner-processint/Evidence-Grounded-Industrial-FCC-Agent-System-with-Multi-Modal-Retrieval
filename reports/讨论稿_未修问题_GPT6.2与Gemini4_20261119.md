## 2. 压矛盾：先固定事实和判断依据，再使用缓存

我建议把事实表放在**多路取证完成之后、首稿和工程解读分叉之前**。同一量在不同问法里也要能找到同一组事实。否则，缓存能让同一句问话稳定复现，换个问法仍可能得到相反判断。

| 办法 | 应怎样落地 | 代价和风险 |
|---|---|---|
| 固定取证路径 | “最新月报”按装置、截至日期、报告期间和发布状态选择。在你们描述的验收快照中应选到 2026 年 6 月；新一期发布后应随之更新。规程先定位版本和位号，再取包含表头、单位、脚注的整行。保留本次查询和命中位置，语义检索补充解释材料。 | 依赖可靠的文档元数据和位号映射。元数据错一次，系统可能稳定地引用错月或错表，因此要用厂方核过的样例检验选期和定位。 |
| 一份事实表，按组呈现多值 | 每条记录带量、对象、期间或工况、数值及原始单位、计算口径、来源位置。先判断是否为可换算的同值，再区分不同工况、不同公式和相同条件下的来源冲突。凡属同一量的多个适用取值，整组交给回答节点，**每个值分别给出处和判断**。 | 最大成本是认定“同一个量”。例如 g/L 与 mg/L 要连同数值换算；两套经验式则要保留各自适用条件。分组错了，会把两个合理结论误判成冲突，或把真实冲突掩盖掉。 |
| 把判断口径也存下来 | 对“一中回流看哪块表”“某股物料是否计入处理量”，记录厂方已确认的定义、适用范围、版本和待确认分支。定义待定时，两种口径分别推导。计算读同一组输入，由代码执行。 | 需要厂方人员确认少数关键定义。某次用户为当前问题指定的口径只在相应范围内生效，写成全厂默认会污染后续回答。 |

**最终核对应检查事实是否被文字忠实保留。** 例如，事实表有两套适用系数，合成稿只写一套，还用它给出唯一结论，就应退回重写。核对依据是事实记录、适用条件和来源 ID，关键数值和引用可以直接从记录呈现。这样比继续在末尾删除“没有”更有效，也符合你们不用词表正则防错的原则。

对现有 19–21 道被模型标为矛盾的题，建议专家先分成四类：**同条件结论冲突、应并列却漏了一支、时间或工况已变化、评分器误判**。第一类计矛盾，第二类计完整性；如果漏写时还明确排除了另一支，就两项都计。否则，一个少说话的系统也可能拿到漂亮的一致性成绩。

## 3. 验收：把首轮、纠正后和一致性分别计分

**先和厂方签定“85% 和 95% 的分母”。** 公司已有“单题专家评分 ≥7 分即成功”的定义。若你们说的准确率也指整题成功率，主指标可直接用“专家判 ≥7 分的题数 / 全部指定题数”。如果还要求关键事实正确，另报“正确覆盖的必答事实 / 全部必答事实”，并单列错位号、错单位、错限值等严重错误。这样一份得了 7 分却写错关键限值的答案，在报告里仍然看得见。

1. **现有题用于诊断，另留专家掌握的盲题用于验收。** 保留公司原细则，由厂方专家在看系统答案前补全可接受的来源、替代口径、多值情形和数值容差。盲题覆盖月报、规程、实时或化验、跨来源计算和追问，加入同义改写与不同工况。冻结资料快照、工作流和模型版本。每题第一次运行即计首轮，超时和只拿到部分证据的题也留在分母里。
2. **让评分器对齐专家的过线判断。** 可先用现有 20 份首稿，请两位专家独立匿名评分，逐项记扣分原因，再裁决分歧。重点数两类错误：模型判过而专家判不过、专家判过而模型判不过。尤其复查 7 分附近和涉及关键装置事实的答案。模型可承担日常回归，正式验收保留专家盲评。已有研究观察到模型裁判受篇幅、呈现顺序等影响，在 FCC 题上的误差仍需用本厂样本测。[NeurIPS 模型裁判研究](https://papers.nips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html)
3. **纠正后 95% 同时报总通过率、纠错成功率和改坏率。** 给每题预设一次现实中用户能给的反馈，例如指定统计月份、确认某股物流是否计入，或指出位号有误。分开记录“确认条件”和“纠正错误”，检查系统有没有重算受影响结论、更新引用、保留其余正确事实。若首轮恰好 85%，且首轮过线题全部保持过线，要达到总体 95%，至少要救回首轮失败题的 **三分之二**。若厂方要求的是“失败题经纠正后有 95% 修好”，那是更高的目标，必须单列。
4. **一致性和出处分别抽验。** 同一快照下，同题冷启动重复跑，再用不同问法问同一事实。报告“出现经专家确认矛盾的题数 / 重复测试题数”，同时报必答事实覆盖率。出处同时看两个比例：**给出的引用中，原文确实支持所述结论的比例**；**全部应举证的关键断言中，有可核验出处的比例**。后一项能发现靠少引来抬高前一项的问题。
5. **把固定题库成绩和对新问题的把握分开报告。** 17/20 就是这套题上的 85%，19/20 就是 95%。即使把它们当作独立代表性抽样，两者的 95% Wilson 区间也分别约为 **64%–95%** 和 **76%–99%**。现有题已经反复用于调试，对新问题的推广更需要独立盲题。同一题重复跑十次可以测稳定性，不能补足题型样本。[NIST 比例置信区间方法](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

## 2. 针对 A 类问题的具体检索 / 路由修法（适配 n8n 流程位置）

所有修法均遵守“靠流程位置、结构化数据、代码计算，不用正则/词表去匹配回答正文”的原则。

### （1）题目不写时段时，如何定位「最新一期月报」
- **前置数据条件（入库侧）**：给 RAGFlow「月报等周期统计」数据集中的每篇文档，规范文件名或外挂一张轻量月报目录索引（记录 `doc_id`、标准期次 `YYYY-MM`、`report_type`）。
- **改动位置 1：「拆题 / 规划」节点**
  - 让规划节点在输出结构化 JSON 时，必须包含时间意图字段：例如明确提问某月时输出 `explicit_period: "2023-11"`；未指定具体时段时，统一输出 `period_mode: "latest_monthly"`（而不是靠改写器自己去拼“2026年”或“最新”这种模糊词进语义检索）。
- **改动位置 2：「检索 / 取数（多路并行）」中的月报专用子分支（加前置 Code 节点）**
  - **独立拆出月报检索支线**：不要把月报和通用技术文档混在一次无过滤检索里。
  - **Code 节点计算目标 `document_id`**：当 `period_mode == "latest_monthly"` 时，由 n8n 节点调用 RAGFlow 数据集文档列表接口（或读轻量月报索引表），用代码按文档名/元数据里的 `YYYY-MM` 降序排序，**确定性地计算出最新一期文档 ID**（如 `2026-06` 对应的 `doc_id`）。
  - **硬过滤检索**：调用 RAGFlow `retrieval` 时显式传入 `document_ids: [latest_doc_id]`，物理屏蔽 2023 年等历史旧月报进入证据包。
  - **补充保底（强烈建议）**：月报本身篇幅有限且核心指标（原料性质、产品收率、运行判断小结）就集中在固定几页；对于“装置运行/原料/产品/催化剂影响”类问题，可直接用 Code 节点按 `latest_doc_id` 附带拉取当期月报的**核心摘要页/固定指标表**作为“当期装置基线”，直接拼进「证据包」，避免只因语义切块分值不够而漏掉关键收率或月报结论。
  - **进入「证据包」前打标**：用 Code 节点为每一条月报召回片段强制加上来源时间前缀（例如 `【2026年6月月报】`），防止后期综合时和其他年份混淆。

### （2）如何按位号到操作规程里定向取控制范围
- **前置数据条件（不靠向量海里捞针，先建两张结构化映射表，存入装置模型库或 Mongo/关系表）**：
  1. **「工艺参数/设备/单元 → 标准位号」映射表**：以厂里现有的 **DCS 画面位号表（1402 个）** 为主干（画面天然带有工段、区域、参数中文描述），合并装置模型库及实时库中已有的 1032 个带描述位号，整理出结构化字段（`tag_id`、`中文名/别名`、`所属画面/工段`、`参数类型`）。先解决核心主控/监控位号映射，不必等另外 1811 个无描述实时库位号全部补齐。
  2. **《操作规程》控制指标与联锁边界结构化表**：把《操作规程》上/下册中的“主要操作指标表”“工艺参数控制范围”“自保联锁一览表”及关键限值（如 `TRCA3101` 480–535 ℃、提降量 ≤25 t/h、`WRCA3101` 30–40 t 等）离线提取成结构化记录（`tag_id`、`指标名称`、`正常控制范围`、`典型控制值`、`报警/联锁值`、`操作约束说明`、`所属规程章节`）。
- **改动位置 1：「拆题 / 规划」节点**
  - 在规划输出的 JSON 中增加两个字段：`explicit_tags`（题干自带位号）和 `process_concepts`（本题涉及的核心工艺概念与工段，如 `["提升管出口温度", "沉降器藏量", "一再藏量", "两器差压", "主风", "滑阀开度"]`）。
- **改动位置 2：「检索 / 取数（多路并行）」中新增「位号与规程指标精准查询」分支**

  - **Step B（结构化查控制范围）**：用映射得到的位号列表（合并 `explicit_tags`）直接精确查询《操作规程》结构化指标表，直接吐出带位号、单位、上下限、自保值和提降量限制的条目。**这一步不走 RAGFlow，既零误差，还能直接减少 RAGFlow 并发数，缓解并发 ≥7 超时/空返回的问题。**
  - **Step C（以位号反查规程正文）**：若还需要操作规程的文字处置说明（如藏量异常怎么办），把 Step A 查出的精确位号（如 `WRCA3101`）和核心词作为 **keyword query**，在 RAGFlow 中仅针对《操作规程》文档用高关键词权重（BM25/全文匹配优先）定向补捞文字段落。
- **改动位置 3：「证据包」拼装节点（Code 节点）**
  - 在证据包里单设固定区块 `【本装置关联位号与操作规程硬约束】`，放最前面或显眼位置，防止在多路文本合并时被长段通识书淹没。

### （3）取数口径那句话（是否需要调实时库 / LIMS 及原因）应由哪一步、依据什么写出来
- **决定“要不要调”和“依据什么”的节点：放在「规划」节点 + 「检索 / 取数」之后的 Code 汇总节点**
  - **判断依据（由「规划」节点输出结构化路由决策 `db_routing`）**：
    1. **时间与对象维度**：问题问的是“普遍规律/机理影响/操作规程静态边界/月度分析回顾”，且**未提及具体日期、班次、实时工况波动、某时刻异常报警或具体批次化验单** → `need_realtime_db = false`、`need_lims = false`，原因枚举设为“机理分析与静态规程/周期月报范畴，不涉及特定时刻实时趋势或特定化验批次”；反之若涉及具体时段排查、实时位号曲线或具体批次原料/平衡剂化验 → 置为 `true` 并给出时间窗和位号。
    2. **实际执行状态（由取数后的 Code 节点核实）**：Code 节点核对“规划是否要求调用”以及“实时库/LIMS 分支是否真正执行并返回了数据”，据此用**确定性模板**生成一条结构化的 `data_scope_statement` 元数据（例如明确写出：本次分析基于静态操作规程及周期月报，因问题聚焦机理与装置静态约束而非某一具体时刻或批次异常，故未调用历史实时库（Mongo）及 LIMS；若用于现场当前异常趋势诊断，需联动调取对应时段 Mongo 实时趋势及 LIMS 化验数据）。
- **写进回答、且不被删改的流程位置：放在「合成」阶段占位 + 「去掉没有」节点之后的最终组装节点**
  - **为什么不能只让「首稿」自己写**：你流程末尾有`合成 → 守卫 → 缺失核对 → 反查环 → 去掉没有`。如果让首稿随便写“未调用实时库”，极容易被「去掉没有」节点当成禁用断言删掉，或者在反查改写时被精简掉。
  - **落地做法**：
    1. 让「合成 / 改写」节点输出结构化 JSON（至少包含正文主体与口径说明槽位），或者把 `data_scope_statement` 单独保存在工作流上下文变量中。
    2. **把最终展示层面的“取数口径说明”放到「去掉没有 / 未检索到类断言」节点之后**（即放在 `背景知识出处标注` 同级或最后 `存会话` 前的最终输出组装节点）：让 Code 节点把前面已经过校对的主体文本与 `data_scope_statement`（或经「合成」节点结合本题场景润色后的无“未检索到”字眼的口径说明段落）按固定版式拼合到指定位置（例如固定置于文末“数据调用与适用口径”或开篇导语）。这样完全由**流程位置和结构化变量**保证 100% 出现，不用正则匹配文字，也不会被前置防错节点误杀。

## 3. 解析失败的表格和扫描版 PDF 的更可靠入库办法

核心思路：**不要把所有异构资料都直接丢给 RAGFlow 的默认通用解析/切块管线**。表格走“结构化数据库 + 行级语义卡片”，扫描专著走“离线拆页 + 强版面 OCR 转 Markdown 再入库”。

### （1）表格类：DCS 控制点统计、设备台账、物料平衡（2024/2025）、停工统计
- **为什么会失败或 0 片段**：工业表格常见合并单元格、多级表头、跨页断表、几十列宽表或纯数字行，通用切块器要么超时内存溢出，要么把表头切没了、因单行太短被当噪音过滤成 0 片段。
- **办法 1（最可靠，主力方案）：拆表入库（装置模型库 / Mongo / 关系数据库），不进 RAGFlow**
  - **DCS 控制点统计、设备台账**：这是标准主数据表。在入库前用脚本（如 Python 处理 Excel）把**合并单元格全部展开填充**，将多级表头压平成单层规范字段（如 `工段_参数名称_报警上限`），清洗掉汇总行/空白行后，直接按行写入数据库。查询时在 n8n 里按位号、设备名、工段做精准检索，100% 准确、不丢失任何一列。
  - **物料平衡、停工统计**：提取成标准化明细表（时间周期、物流名称、流量、收率、停工起止时间、原因等）存入数据库，支撑精准统计和跨期对比。
- **办法 2（辅助语义召回）：外部线性化后再进 RAGFlow**
  - 若是 PDF 格式的物料平衡或停工统计表，先用专门的版面/表格解析工具（如 **MinerU**、**Docling**，或用多模态视觉模型按页转成 Markdown/CSV 並人工抽检核对关键数字）。
  - 进 RAGFlow 前**不要传原表格**，而是转换成两类可控文本再切片：
    - 对台账/控制点类：一行一条生成**自包含的键值对文本卡**（每行都显式带出表头与所属工段，如 `【DCS控制点 | 反再工段】位号：...，描述：...，量程：...，高报：...`），严禁一行和表头被切在两个 chunk 里。
    - 对物料平衡/停工统计这类窄而完整的表：按**“单期一张完整 Markdown 表 + 一段文字摘要（标明时间、总进料、主要产品收率/停工关键原因）”**作为一个整体独立切片，**禁止切分器在表格中间断开**。

### （2）扫描版 / 复杂排版 PDF：《催化裂化化学与工艺》等化工专著
- **为什么会失败**：老版化工专著常是双栏扫描件、字迹噪点多，还夹杂大量分子式、反应机理图、热力学公式与图表，单本几百上千页，直接丢进 RAGFlow 极易导致内置 OCR 超时或崩溃。
- **更可靠的离线预处理流水线（适配你们未来离线部署需求）**：
  1. **按章拆分小文件**：先按目录用 PDF 工具把整本大书拆成按章划分的小 PDF（每份 20–50 页）。单章失败可单独重跑，不会整本书解析归零。
  2. **外部专用版面解析转 Markdown**：绕开 RAGFlow 自带的 PDF 解析器，在外部用更强的版面与公式识别方案（可本地部署 **MinerU / Magic-PDF**、**Docling**，或本地 **Qwen2.5-VL / Qwen3-VL** 类多模态视觉模型逐页识别）把 PDF 转换成干净的 Markdown（双栏自动按阅读顺序还原、公式转 LaTeX、书内小表转 HTML/Markdown）。
  3. **关键插图转文字描述**：化工书里的活性对比曲线、反应路径图、两器示意图往往藏着关键结论，可用视觉模型给插图生成详实的图注描述插回正文对应位置。
  4. **文本清洗与“结构化标题路径”预切片后入 RAGFlow**：清掉页眉页脚页码与跨页断行，按 Markdown 标题层级（章/节/小节）做语义切块，并在每个 chunk 开头强制加上**书名 + 章节路径 + 原书页码**（例如 `【《催化裂化化学与工艺》> 第X章 > 第Y节 (P.123)】`）。
  5. **导入方式**：把处理好的干净 Markdown（或切好的块）导入 RAGFlow，让 RAGFlow 只做向量化和检索索引，不承担高风险的 PDF 解析任务。这样做还能顺便为你们的 **F 类问题（原书核对出处）** 提供精准的章节页码定位。

## 4. 两份回答除了数据缺失，写法上还会让专家打低分的地方

把数值和位号缺口先拿掉，单看这两份回答的文本组织与表达方式，炼油工艺专家在盲评时主要会在以下 5 个方面扣分：

1. **“AI 证据审查报告腔”太重，不像给现场工艺人员看的运行解答**
   - 专家想看的是“机理怎么回事 → 装置上会落到哪里 → 现场怎么盯、怎么判、怎么调、红线在哪”。
   - 这两份回答通篇在向读者交代“证据质量与检索边界”：QS001 特意在表格里设了一整列“证据性质”，第三部分大段论证“为什么本轮资料不能做定量预测”；QS020 不断声明“属于对机理的推断”“属于可能性推断”“证据正文并未给出实测支持”。在专家看来，这非常像智能体在汇报自己的文献综述局限，而不是在辅助生产判断，实用性分会被拉低。

2. **过度“防错式免责”，把业内公认的工艺定论也降格成“推断”**
   - 例如 QS001 写“密度升高**可能**反映芳烃与胶质沥青质比例上升……这一解释与上述方向一致，**但属推断**”“瓶颈**可能**不在产品收率，而在再生器热平衡与烟气系统……**这一判断属工程推断，需核实**”。这些在 FCC 里属于教材级基本因果，强行打上“可能”“属推断”，会让专家觉得问答系统对基础机理没有把握、不敢下判断。
   - 同理，QS020 把“料封不足导致压差扰动敏感、热容缓冲变小导致床温波动加快”也标为“属于对机理的推断”，主次感反而变弱。

3. **存在逻辑自相矛盾，以及直接把问题“甩回给用户”的收尾**
   - **自相矛盾**：QS001 第一节开头说密度与残炭升高使“焦炭收率上升”，紧接着引用 `[E3]` 又写了“综合效应是……转化率下降、**焦炭及汽油产率降低**”。即使原文献算例在某种特定限制下有此数字特征，不加前提解释直接把“焦炭上升”和“焦炭降低”挨着写，专家会直接判为逻辑矛盾。
   - **甩锅式结尾（且违反你们自己的“不说没有”原则）**：QS020 专门列了一个 `## 不能判定的部分`，直白写出“本轮证据……没有给出本装置藏量的具体控制指标……也没有给出实测数据……**需要查阅本装置操作规程中的藏量控制范围**……”。这种暴露系统没找到资料、叫用户自己去翻规程的写法，在盲评里很伤观感；而且“去掉没有”这一步明显漏掉了这种变体表达。

4. **缺乏一线操作视角：缺少“防踩坑红线”、优先排查顺序和口径区隔**
   - **缺防呆/操作红线**：QS001 没有提醒现场最常见的误区——汽油下降时不能简单靠大幅提高反应温度去追转化率（会挤压主风、再生床温、取热和二次裂化约束）。
   - **主次视角偏离生产实际**：QS020 讲“藏量过高不利”时，把大段篇幅给了偏长周期的“置换率下降、平衡活性降低”，却把现场两器运行更直接面临的“床层压降升高、稀相夹带与旋分负荷增加、磨损、汽提不良与流化恶化”压得很轻甚至一笔带过；排查顺序也抽象在“压差与阀位增益”上，却漏掉了现场最基础的第一步——**先核实仪表、密度和料位测量是否失真**。
   - **口径未主动隔离**：QS001 一处谈原料金属变化，一处写“平衡剂 Ni+V 达到 17500 ppm”，没有顺手点明“原料金属浓度（mg/kg）”与“平衡剂金属累积含量（ppm）”是两个不同对象的口径，容易让专家觉得概念混用。
   - **文字密度低、缺少一分钟抓手**：两份正文都是近 3000 字的长段落，表格只是在复述正文语句，缺少简洁的“联查变量清单 / 排查 1-2-3 步 / 边界红线”小模块，专家阅读负担大。

5. **证据编号 `[E1]` `[E2]` 脱离出处名称，不方便盲评核验**
   - 正文里满篇 `[E1]–[E17]`，但除了行文偶尔提到“2023 年 11 月”，在展示出来的回答正文中**看不到 `[E1]` 分别对应哪份月报、哪本规程或哪本专著**（如果在你们完整输出文末也没有附上 `[E*]` 映射清单的话）。把“通识书理论算例”和“本装置某年某月运行记录”统一用无差别的 `[E*]` 混编，盲评专家既分不清哪句出自本装置还是通识书，也无法现场核对出处，会直接拖累“出处可验证率”。（如文末其实有附 `[E*]` 出处清单、只是本次截取未包含，则此条当我未看到全貌、仅作提示。）
